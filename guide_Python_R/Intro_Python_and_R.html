STIP Survey 2025 data analysis guide

A practical introduction using Python and R

Authors: Benjamin Bjerkan-Wade, David Howoldt, Rei Tomoe and Daniela Valenzuela

Introduction

This data story provides a step-by-step guide to working with STIP Compass data. It explains what datasets are made available by the STIP Data Lab, the variables they include, and how to work with them in Python and R. It also highlights the relationship of policy initiatives and instruments and common pitfalls in analysing them. This data story provides first step elements for analysts and researchers to consider when starting to analyse STI policies, from basic operations to practical analytical examples. The full code accompanying this guide is available on GitHub. Readers can download the R or Ipynb file to execute the code and follow the steps on their own devices.

The STIP Compass portal offers a variety of tools to gain insights from the collected data. For those who prefer more control, a custom approach, or need reproducible results, working directly with the dataset can be highly beneficial. The dataset is derived from the STIP Survey, which systematically collects both quantitative and qualitative data on national science, technology, and innovation (STI) policies. This survey covers a broad spectrum of STI policy areas from over 60 territories and the EU. This is an introduction to working with the STIP Survey data, providing a step-by-step guide for accessing, understanding and analysing the dataset using Python and R.

1. Available datasets

The STIP Data Lab makes available several datasets, corresponding to the five survey waves completed since the inception of the STIP Compass in its current form in 2017, as well as datasets resulting from previous data collection activities on STI policies (see the list of datasets here). The most recent dataset is the 2025 'live database', comprising all policy initiatives reported in the most recent survey wave and all updates made to that data since then (countries have continuous access to the survey tool also after the conclusion of a survey wave). The 'live database' is updated every few months by synchronising the STIP Compass database with the data in an online tool where STIP Survey respondents provide data. For most cases, using the 'live database' for analysis is recommended, as it contains the most recent policy data.

2. Setting up the analysis environment

STIP Survey data can be analysed in multiple ways. While MS Excel provides one option, it often becomes less efficient and slower when handling large datasets. To ensure a more streamlined, flexible, and reproducible process, popular programming languages such as Python and R are recommended. Both languages are capable of performing the same types of analyses, allowing the readers of this guide to select the one that best align with their preferences.

Properly setting up the programming environment is important as to ensure a smooth working environment. The setup process for each environment is outlined below.

Python environment setup

When using Python, users will need the following libraries:

  • pandas: Data loading and manipulation
  • matplotlib and seaborn: Data visualization (used in visualization sections)

R environment setup

When using R, users will need the following packages:

  • data.table: Efficient data loading
  • dplyr: Data manipulation
  • ggplot2: Data visualization
  • tidyr: Data reshaping

3. Data download and loading

As mentioned, STIP Survey 2025 data can be downloaded directly from the STIP Data Lab. We recommend using the latest 'live database', which represents the most comprehensive dataset containing the most recent survey results and continuous updates. In this case, "https://stip.oecd.org/assets/downloads/STIP_Survey.xlsx" provides a direct access link to the dataset.

For a more focused analysis, it is also possible to manually filter the STIP Survey data based on specific parameters such as policy instruments, themes and target groups prior to downloading. This can be done on the STIP Data Lab download page, where users can customize the dataset according to their needs and then export it as a CSV or XLSX here.

4. Variables in the dataset

When the dataset loads successfully, users can confirm that it contains over 12,000 records and more than 500 columns. The most important columns can be classified in four groups: policy initiatives, themes, target groups, and policy instruments. Further context can be found in the publicly available survey data model. The four groups are explained below:

  • Policy initiatives: The leftmost columns provide information on policy initiatives, the STIP Survey's main unit of reporting, and correspond to the 'policy initiative fiche' described in the data model. They contain qualitative as well as quantitative information.
  • Themes: A set of columns with names starting with "TH". These are dummy columns indicating membership of policy initiatives with different themes. The current STIP Survey has 53 themes, which correspond to the different questions addressed to survey respondents. Policy initiatives are linked to one or more themes.
  • Target groups: A set of columns with names starting with "TG". These are dummy columns indicating the direct beneficiaries (or 'Target Groups') of policy initiatives. The current STIP Survey specifies 34 types of direct beneficiaries. Policy initiatives have one or more direct beneficiaries.
  • Policy instruments: The remaining columns describe the policy instruments associated with policy initiatives. The data model comprises 28 instrument types, denoted in the 'InstrumentTypeLabel' column. All columns starting with letter F followed by a number describe instrument facets as specified in the data model, these are sub-fields of the policy instruments that contain more details to characterise them. There are 383 columns of this type, and analysts mainly interested in policy initiatives might disregard their content.

The data model specifies that policy themes, direct beneficiaries and policy instruments are organised using two-level coding schemes, with smaller sets of broad categories at the first level (For example for instruments, Governance) and more specific instances under these categories at the second level (For example, under Governance, eight policy instruments exist, from Strategies, agendas and plans to Public awareness campaigns and other outreach activities). The dataset only provides information on the second, more granular level for the first level, please consult the data model.

The first row of the dataset below the header contains additional detail on the content of columns, rather than observational data. It helps understanding the links between the dataset and the data model. Using this information and the data model, analysts can infer the label category for each observation in the dataset.

5. Data cleaning and codebook creation

The dataset contains information about policy themes (columns starting with "TH") and target groups (columns starting with "TG"). These columns need to be properly processed as numerical data and cleaned for analysis use.

Data preprocessing

The first row of the dataset contains variable descriptions, so it needs to be removed to keep only observational data. In addition, columns starting with "TH" and "TG" should be converted to numeric format for analysis.

Data cleaning and codebook creation: Python vs R

The following code examples show how to create a codebook and clean the data for analysis in both languages:


# To facilitate working with the dataset, we generate a separate 'Codebook' dataframe 
# listing the column names and the detail given in the first row, for variables on themes and direct beneficiaries

codebook = pd.DataFrame({

Understanding policy initiatives and policy instruments

In the STIP Survey, policy initiatives are defined as a public action that:

  1. Aims to achieve one or several public policy goals in the policy area of science, technology and innovation.
  2. Is expected to modify or frame the behaviour of actors and stakeholders, being national, domestic or foreign, who are part of or influential on, the national innovation system, and
  3. Is implemented with a minimum time horizon or on a continuous basis (i.e. not as a one-off "event").

The first column of the dataset provides the IDs of initiatives. They are written as Unique Resource Identifiers, with the actual ID of each initiative denoted by a string of numbers following the final backslash. Free text fields provide information about the names of initiatives, short descriptions, and objectives. Budget information and the names of the organisations responsible for the implementation of initiatives are also provided.

Policy instruments, on the other hand, are the tools and mechanisms used to implement policy initiatives. For the 28 instrument types included in the dataset, the column 'InstrumentTypeLabel' indicates the type of each dataset. The data model specifies as broad instrument categories: Governance; Direct financial support; Indirect financial support; Collaborative infrastructures (soft and physical); and Guidance, regulation and incentives.

A policy initiative can have one or more policy instruments. Importantly, rows in the dataset correspond to individual policy instruments. If an initiative comes with more than one policy instrument, it occupies several rows in the dataset, with the initiative-level information being repeated across these rows, and distinct instrument information in each row. Therefore, to simplify the analysis is important to remove duplicative policy initiatives.

Removing duplicate policy initiatives

As explained above, in the STIP Survey dataset, when a single policy initiative has multiple policy instruments, it is recorded across multiple rows. To accurately understand the number of policy initiatives, we need to remove duplicates.

For both policy themes and direct beneficiaries, the second level of coding is provided in the dataset analysed here, whereas the broad thematic areas/groups can be inferred from the data model referred to above.

The 53 policy themes in the dataset fall into seven broad thematic areas described in the data model: Governance; Public research system; Innovation in firms and innovative entrepreneurship; Knowledge exchange and co-creation; Human resources for research and innovation; Research and innovation for society; and Net zero transitions.

6. Basic analysis

To give an example of a theme-based analysis of the dataset, we turn to policy initiatives concerned with the financing of innovation in firms. The STIP Survey contains four themes relevant in this context that can easily identified in the codebook: Financial support to business R&D and innovation (TH31); Non-financial support to business R&D and innovation (TH32; Foreign direct investment (TH36); and Access to finance for innovation (TH38). The direct beneficiaries of policy initiatives could be analysed in a similar way.

A) Comparison of policy instruments versus initiatives by theme

Analysis: Python vs R


# Import necessary libraries for visualization
import matplotlib.pyplot as plt
import seaborn as sns

# --- 1. Remove columns that start with "F" (make a copy to avoid SettingWithCopyWarning) ---
financing_innovation = stip_survey.loc[:, ~stip_survey.columns.str.startswith('F')].copy()

# --- 2. Filter rows where at least one of the target themes is present ---
theme_cols = ['TH31', 'TH32', 'TH36', 'TH38']
# Ensure theme columns are numeric
financing_innovation[theme_cols] = financing_innovation[theme_cols].apply(pd.to_numeric, errors='coerce')
# Keep rows where the sum of these columns is greater than 0
financing_innovation = financing_innovation[financing_innovation[theme_cols].sum(axis=1) > 0]

# --- 3. Reshape to long format for the four themes ---
financing_long = financing_innovation.melt(
    id_vars=[col for col in financing_innovation.columns if col not in theme_cols],
    value_vars=theme_cols,
    var_name='Theme',
    value_name='value'
)
# Keep only rows where the theme is present (value == 1)
financing_long = financing_long[financing_long['value'] == 1]

# --- 4. Count the number of instruments per InitiativeID and Theme ---
grouped = financing_long.groupby(['InitiativeID', 'Theme']).size().reset_index(name='n_instruments')

# --- 5. For each Theme, keep only unique InitiativeID and summarize ---
unique_initiatives = grouped.drop_duplicates(subset=['Theme', 'InitiativeID'])
summary = unique_initiatives.groupby('Theme').agg(
    n_initiatives=('InitiativeID', 'nunique'),
    n_instruments=('n_instruments', 'sum')
).reset_index()

# --- 6. Map theme codes to descriptive labels for plotting ---
theme_labels = {
    'TH31': 'Financial support to business R&D and innovation',
    'TH32': 'Non-financial support to business R&D and innovation',
    'TH36': 'Foreign direct investment',
    'TH38': 'Access to finance for innovation'
}
summary['Theme_label'] = summary['Theme'].map(theme_labels)

# --- 7. Reshape summary for plotting (long format) ---
plot_df = pd.melt(
    summary,
    id_vars='Theme_label',
    value_vars=['n_initiatives', 'n_instruments'],
    var_name='Type',
    value_name='Count'
)

# --- 8. Plot grouped horizontal bar chart ---
plt.figure(figsize=(10, 6))
sns.barplot(
    data=plot_df,
    y='Theme_label',
    x='Count',
    hue='Type',
    palette=['skyblue', 'steelblue']
)
plt.title('Policy Initiatives and Instruments for Innovation in Firms', fontsize=16)
plt.xlabel('Count')
plt.ylabel('')
plt.legend(title='', loc='center left', bbox_to_anchor=(1, 0.5))
plt.tight_layout()
plt.show()


financing_innovation <- stip_survey %>%

  dplyr::filter(rowSums(across(c(TH31, TH32, TH36, TH38), ~ replace_na(.x, 0))) > 0) %>% #filter to retain only the policy themes in question
  tidyr::pivot_longer(c(TH31, TH32, TH36, TH38), names_to = "Theme", values_to = "value") %>% #change the format of the dataframe to enable separate analysis of the four themes
  dplyr::filter(value == 1) %>%
  dplyr::group_by(InitiativeID, Theme) %>%

  dplyr::group_by(Theme) %>%

The figure below shows that there are more policy instruments than initiatives for each theme; this is a reflection of the data set, as each policy initiative comes with one or several policy instruments. The analysis also shows that the ratio of policy instruments and initiatives varies. For some themes, there are markedly more instruments than initiatives, while for others, the number of instruments does not exceed the number of policy initiatives by much. This indicates that the choice of policy instruments implementing a policy initiative varies depending on their theme.

B) Identifying top instrument for a specific theme

Now we can analyse which policy instruments are most commonly used in policy initiatives related to the specific theme Non-financial support to business R&D and innovation (TH32).

Analysis: Python vs R

The following code shows how to identify the top 5 instrument types for non-financial support policies in both languages:


import matplotlib.pyplot as plt
import seaborn as sns

# 1. Remove columns that start with "F"
th32_instruments = stip_survey.loc[:, ~stip_survey.columns.str.startswith('F')]

# 2. Filter rows where TH32 > 0 (ignore non-numeric rows)
th32_instruments = th32_instruments[
    pd.to_numeric(th32_instruments['TH32'], errors='coerce') > 0
]

# 3. Group by 'InstrumentTypeLabel' and count occurrences
th32_instruments = (
    th32_instruments
    .groupby('InstrumentTypeLabel')
    .size()
    .reset_index(name='n')
)

# 4. Get the top 5 by count, descending order
th32_instruments = th32_instruments.nlargest(5, 'n').sort_values('n', ascending=False)

# 5. Plot
plt.figure(figsize=(10, 6))
sns.barplot(
    data=th32_instruments,
    y='InstrumentTypeLabel',
    x='n',
    color='skyblue'
)
for x in [20, 40, 60, 80, 100,120]:
    plt.axvline(x, color='gray', linestyle='--', lw=1, zorder=0)
sns.despine(left=True, bottom=True)
plt.title('Top 5 Instrument Types for Non-financial support to business R&D and innovation', fontsize=16)
plt.xlabel('Number of Instruments')

plt.ylabel('')
plt.tight_layout()
plt.show()

Taking a closer look, the figure below maps the policy instruments supporting the implementation of policy initiatives linked to the theme 'Non-financial support to business R&D and innovation'. It plausibly shows that instrument types related to advisory services and networking and collaboration are most prominent among these initiatives. The presence of an instrument type about grants for business R&D and innovation suggests that policy initiatives under this theme might at the same time also provide financial support for business R&D. This is not surprising as policy initiatives often span several themes at the same time.

7. Summary and conclusions

This data story has provided an introduction to using STIP Survey data with Python and R, from downloading the dataset to explaining its structure and contents and to presenting basic steps for its analysis. By the end of this story, readers should have gained a solid understanding of:

  • How to obtain the latest live database from the STIP Data Lab.
  • Basic data cleaning techniques, including deduplication of policy initiatives.
  • How to explore the data structure and relationships among policy initiatives, themes, target groups, and policy instruments.
  • How to conduct basic analyses, such as theme-based exploration to identify common types of instruments.

These should serve as initial steps into analysing the wealth of data available in STIP Compass. Working directly with the dataset can be highly beneficial, especially for users who prefer more control, a custom approach, or need reproducible results. As highlighted, data users should be cautious with regard to the structure of the dataset and be mindful of the differences between policy initiatives and policy instruments when analysing the dataset.
